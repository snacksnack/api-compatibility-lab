# ADR 0008: publishing the reports as a site (RC1-620)

Status: accepted
Date: 2026-11-06

## Context

Seven phases produced four reader-facing reports, seven ADRs and three probe
logs, all committed under `docs/` and all regenerated and diffed by CI. None
of them was reachable on the web.

`docs/impact-report.html` is the sharpest version of the problem. It is
written by `compatlab impact --html` as a self-contained, zero-JavaScript page
with its own stylesheet, built to be the artifact an FDE sends the customer
who asked whether the upgrade will break them. GitHub serves a committed
`.html` blob as highlighted source, so the one artifact in this repository
designed to be looked at was the one artifact nobody could look at. The
portfolio card pointed at the markdown twin instead.

Output: `publish/` (the site build), `compatlab/theme.py` (the stylesheet and
document shell, moved out of `compatlab/impact_html.py`), the `site`
dependency group, `.github/workflows/pages.yml`, and a repointed link on the
`/work` card.

## D1. Deploy from main with Actions, not by force-pushing a built branch

`agent-evals` publishes by building a page and force-pushing it to `gh-pages`,
and that is right for it: its artifact is rendered from a live database, so
keeping it out of `main`'s history is the point of the exercise.

Nothing here is like that. This repository's reports are committed, and four
CI gates exist to prove they are current. A built branch would add a second
copy of an artifact that is already under review, and the obvious failure is
the copy going stale while the gate stays green.

So the site is built by Actions from `main` and never committed. `site/` is
gitignored. The build also runs on pull requests, where it does not deploy:
a broken link fails review rather than the published site.

## D2. One stylesheet, in one file, used by both

The impact report and the site are the same work seen by two readers, so they
are not two designs. `CSS` moved verbatim into `compatlab/theme.py` and both
import it; a change to a hairline or a status color can no longer land on one
and miss the other.

`SITE_CSS` is separate and additive, covering what markdown produces and a
generated report never contains: navigation, links, block quotes, preformatted
blocks. Keeping it out of `CSS` is what lets the committed report regenerate
byte-for-byte unchanged, which is the check that proved this refactor was
behavior-neutral.

## D3. The site wraps the delivered report; it does not re-render it

The published impact report is the committed file with the site's header and
footer spliced in at asserted seams, not a second render from the same
objects.

A second render would have to reassemble the report from the replay record,
the findings, the baseline index and the adjudication file, duplicating the
orchestration in `compatlab impact`. Two paths producing one customer-facing
number is how they come to disagree, and the version that disagrees would be
the one on the public internet. `test_the_published_impact_report_is_the_committed_one`
asserts the committed body survives into the published page, so a future
attempt to re-render it fails rather than quietly diverging.

## D4. A link that resolves to nothing fails the build

Every relative link under `docs/` is written to work on disk and on GitHub,
and `tests/test_engagement.py` enforces the first of those. Neither convention
survives publication: `regression-tests.md` is not a page on this site, and
`pinned/test_pinned_behavior.py` is not on it at all.

So each link is resolved against its own file and then either pointed at the
page rendering that document or sent to the source on GitHub, with a
directory becoming a `tree` URL and a file a `blob` URL. A target that
resolves to nothing, or outside the repository, raises and fails the build.
The alternative is a 404 that only a reader finds, which on a page whose
argument is "every claim traces to an artifact" is worse than a red build.

`docs/impact-report.md` is not published, because it is the same content as
the HTML report and publishing both invites a reader to guess which is
current. The five documents that link to it are aliased onto the HTML page.

## D5. Autolinks are off, because the tokens outrank the renderer

This repository's canonicalized values are angle-bracketed and look like URIs
with a scheme: `<id:pi>`, `<ts+30d>`. CommonMark reads them as autolinks, and
the first build published `<id:pi>` as a link to `id:pi`.

The prose carrying those tokens is generated by `compatlab/impact.py`, and it
feeds `PinnedTest.fingerprint` — deliberately, so that certifying a pin and
then changing what it asserts cannot go unnoticed (ADR 0006). Rewriting the
token to satisfy a markdown renderer would therefore invalidate all 21 live
certifications, which need a Stripe key and a hand-run double replay to
rebuild. The renderer is the cheaper thing to bend: no document here uses a
bare autolink, and a test keeps it that way.

## D6. The index is the engagement writeup

Not a landing page written for the occasion. The writeup already states the
question, the numbers and the limits in that order, and every other document
is something it links to; a new page in front of it would be a second summary
to keep true.

Rendering it did turn up two stale claims it had been carrying — a corpus that
"exercises half the documented breaks" after RC1-618 took that to seven of
eight, and a reference to the epic as in-flight. Both are fixed, and the first
is the argument for publishing: a figure nobody looks at is a figure nobody
checks.
